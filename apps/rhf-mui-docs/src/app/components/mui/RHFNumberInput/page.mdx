# RHFNumberInput

`RHFNumberInput` is a
[TextField](https://mui.com/material-ui/react-text-field/)-based numeric input
that enforces number-only entry, with options for integers-only, non-negative
values, a maximum number of decimal places, and keyboard step increments. The
value stored in your form is a real `number`, or `null` when the field is empty.

## Usage

```tsx
import RHFNumberInput, { RHFNumberInputProps } from '@nish1896/rhf-mui-components/mui/number-input';
```

```tsx
import { useForm } from 'react-hook-form';

type FormValues = {
  age: number | null;
};

const { control, handleSubmit } = useForm<FormValues>({
  defaultValues: { age: null }
});

<form onSubmit={handleSubmit(values => console.log(values))}>
  <RHFNumberInput
    fieldName="age"
    control={control}
    onlyIntegers
    nonNegative
  />
</form>
```

Use `undefined` or `null` as the default value for an empty field.

### Restricting input

`RHFNumberInput` rejects invalid keystrokes and pasted text up front, instead of
correcting them afterwards. Combine the props below to describe the numbers you
accept. The characters `e`, `E` and `+` are always blocked, and so is a second
minus sign.

#### Integers only

`onlyIntegers` blocks the decimal point. A pasted decimal is cut to its whole
part, so `43.234` becomes `43`. Stepping also moves by whole numbers:
`stepAmount` is rounded down, with a minimum of `1`.

```tsx
<RHFNumberInput
  fieldName="quantity"
  control={control}
  onlyIntegers
/>
```

#### Non-negative values

`nonNegative` blocks the minus sign, typed or pasted, so a pasted `-43.5`
becomes `43.5`.

```tsx
<RHFNumberInput
  fieldName="price"
  control={control}
  nonNegative
/>
```

#### Decimal places

`maxDecimalPlaces` limits the digits after the decimal point. The user can't
type more, and a pasted `3.14159` becomes `3.14` when the limit is `2`. Don't
combine it with `onlyIntegers`.

```tsx
<RHFNumberInput
  fieldName="weight"
  control={control}
  nonNegative
  maxDecimalPlaces={2}
/>
```

#### Step amount and markers

Arrow keys step the value by `stepAmount` (default `1`). The native up/down
markers are hidden by default; set `showMarkers` to show them.

```tsx
<RHFNumberInput
  fieldName="quantity"
  control={control}
  onlyIntegers
  stepAmount={5}
  showMarkers
/>
```

#### Minimum and maximum

The `min` and `max` props set the lower and upper bounds. Stepping with the
arrow keys or the markers stops at them. Typing and pasting are **not** blocked
while the user is editing, so the field can briefly hold an out-of-range number,
such as `7` on the way to `70`. When the field loses focus, an out-of-range
value is clamped to the nearest bound and the new value is stored in the form.

`nonNegative` sets the lower bound to `0`, and an explicit `min` overrides it. A
`min` greater than `max` throws an error.

```tsx
<RHFNumberInput
  fieldName="age"
  control={control}
  onlyIntegers
  min={18}
  max={65}
/>
```

Because the bounds are applied on blur, add `min` / `max` rules in
`registerOptions` as well (see [Validation](#validation)) if you want a message
while the user is still typing.

#### Formatting the displayed value

The `renderValue` prop formats the number for display: thousands separators, a
currency prefix, fixed decimals. The field switches to `type="text"` (which can
render grouping characters) and shows the formatted string only while it is
**not** focused. On focus it reverts to the raw number and every typing, paste,
`min` and `max` rule still applies. The stored value stays a real `number |
null`.

```tsx
<RHFNumberInput
  fieldName="salary"
  control={control}
  nonNegative
  maxDecimalPlaces={2}
  renderValue={value => value === null
    ? ''
    : value.toLocaleString('en-IN', {
      style: 'currency',
      currency: 'INR'
    })
  }
/>
```

### Validation

Bounds and required checks belong in `registerOptions`. Because the value is a
number, `min` and `max` compare numerically, and the messages show through the
same error state as every other field:

```tsx
<RHFNumberInput
  fieldName="age"
  control={control}
  onlyIntegers
  nonNegative
  helperText="Between 18 and 65"
  registerOptions={{
    required: 'Age is required',
    min: { value: 18, message: 'You must be at least 18' },
    max: { value: 65, message: 'Age cannot exceed 65' }
  }}
/>
```

`required` treats `null` as empty. Use `validate` for anything more specific:

```tsx
registerOptions={{
  validate: value =>
    value === null || value % 5 === 0 || 'Enter a multiple of 5'
}}
```

### Handling value changes

`onValueChange` runs after the new value has been stored in the form. It
receives `{ newValue, event }`, where `newValue` is a `number` or `null`:

```tsx
<RHFNumberInput
  fieldName="quantity"
  control={control}
  onlyIntegers
  onValueChange={({ newValue, event }) => {
    setTotal((newValue ?? 0) * unitPrice)
  }}
/>
```

Use `customOnChange` when you need to change what gets stored. It replaces the
default handling, so you must call `rhfOnChange` yourself with the value to
store. This example caps the value at 100: `onValueChange` is **not called**
when `customOnChange` is used.

```tsx
<RHFNumberInput
  fieldName="quantity"
  control={control}
  onlyIntegers
  customOnChange={({ rhfOnChange, newValue, event }) => {
    rhfOnChange(newValue === null ? null : Math.min(newValue, 100));
  }}
/>
```
