# RHFCountrySelect

`RHFCountrySelect` is an
[Autocomplete](https://mui.com/material-ui/react-autocomplete/) pre-loaded with
a list of <MuiLink href={externalLinks.githubRepo.countriesList} target="_blank"
rel="noopener noreferrer">250 countries</MuiLink> (**flag**, **name**, **ISO**
and **ISO3** code). Store the complete `CountryDetails` object, or a single
property via `valueKey`. Pin common choices with `preferredCountries`.

## Usage

```tsx
import RHFCountrySelect, {
  RHFCountrySelectProps,
  CountryISO,
  CountryDetails,
  countryList
} from '@nish1896/rhf-mui-components/mui/country-select';
```

Without a `valueKey`, the stored value is the whole `CountryDetails` object, or
`null` when nothing is selected:

```tsx
import { useForm } from 'react-hook-form';

type FormValues = {
  country: CountryDetails | null;
};

const { control, handleSubmit } = useForm<FormValues>({
  defaultValues: { country: null }
});

<form onSubmit={handleSubmit(values => console.log(values.country?.name))}>
  <RHFCountrySelect
    fieldName="country"
    control={control}
    registerOptions={{ required: 'Please select a country' }}
  />
</form>
```

`onValueChange` receives `{ newValue, event, reason, details }`: the value that
was stored, the original change event, and Material UI's change `reason` and
`details`.

The label, helper text and error props work as described in
[RHFTextField](/components/mui/RHFTextfield).

### Country data

Each country is an object with a `name`, an `iso` code, an `iso3` code and an
`emoji` flag:

```js
{
  name: 'India',
  iso: 'IN',
  iso3: 'IND',
  emoji: '🇮🇳'
}
```

The `iso` key is strongly typed as `CountryISO`, which keeps
`preferredCountries` and your own code type safe. The full list of 250 countries
is exported as `countryList`, so you can read or filter it yourself.

### Choosing the stored value

Set `valueKey` to store a single property of the country instead of the whole
object. It can be `iso`, `iso3` or `name`.

| `valueKey` | Stored value for India |
|---|---|
| none | `{ name: 'India', iso: 'IN', iso3: 'IND', emoji: '🇮🇳' }` |
| `iso` | `'IN'` |
| `iso3` | `'IND'` |
| `name` | `'India'` |

```tsx
const { control } = useForm<{ nationality: string | null }>({
  defaultValues: { nationality: null }
});

/* stores "IND" for India, "AUS" for Australia */
<RHFCountrySelect
  fieldName="nationality"
  control={control}
  valueKey="iso3"
/>
```

The stored value is also how a country is matched. With a `valueKey`, a country
is matched by that property, and a stored value that isn't in the list isn't
shown as selected.

When `valueKey` is omitted, countries are matched by `iso`, so an object loaded
from your API matches as long as its `iso` is the same. Clearing the field
stores `null`, or `[]` with `multiple`, unless `disableClearable` is set.

### Customizing the country list

By default every country in `countryList` is listed in the options. Pass the
`countries` prop to render only the ones you need.

```js
const filteredCountries = countryList.filter(country => (
  ['IN', 'US', 'AU', 'FI', 'UA', 'CN', 'GB', 'JP', 'VN'].includes(country.iso)
));
```

`preferredCountries` pins countries to the top of the dropdown, by `iso` code.
They appear in the order you list them, followed by the remaining countries in
their usual order. A pinned country isn't repeated further down, and a code that
isn't in the list is ignored. It only changes the order of the options, not the
value.

```tsx
<RHFCountrySelect
  fieldName="dreamDestinations"
  control={control}
  countries={filteredCountries}
  preferredCountries={['IN', 'AU', 'JP']}
  valueKey="name"
  multiple
/>
```

### Multiple selection

Set `multiple` to store an array: of whole country objects, or of the `valueKey`
property when one is set. Use `[]` as the default value. Each selection is shown
as a chip, and the menu stays open while the user picks.

While the field is not focused, only the first `limitTags` chips (default `2`)
are shown, followed by a chip such as "+1 Country" or "+3 Countries".
`limitTags={-1}` shows all of them, and `getLimitTagsText` receives the number
of hidden chips and returns your own text. `ChipProps` customizes the chips.

```tsx
const { control } = useForm<{ countriesVisited: string[] }>({
  defaultValues: { countriesVisited: [] }
});

<RHFCountrySelect
  fieldName="countriesVisited"
  control={control}
  valueKey="iso"
  multiple
  limitTags={3}
  getLimitTagsText={hidden => `+${hidden} more`}
  ChipProps={{ color: 'primary', size: 'small' }}
/>
```

### Custom option labels

Each option shows the country's flag and name by default. `renderOptionLabel`
replaces that content. It receives the country and a state object with
`selected`, `index`, `inputValue` and `disabled`.

```tsx
<RHFCountrySelect
  fieldName="country"
  control={control}
  renderOptionLabel={(option, { selected }) => (
    <span style={{ fontWeight: selected ? 700 : 400 }}>
      {option.emoji} {option.name} ({option.iso3})
    </span>
  )}
/>
```

### Input and behavior

`textFieldProps` is forwarded to the underlying `TextField`, for example a
`placeholder`, `variant` or `size`. `autoHighlight` is `true` by default, so the
first match is highlighted as the user types and Enter selects it.
`disableClearable` removes the clear button. Only countries from the list can be
selected, so `freeSolo` is **not supported**.

### Handling value changes

`onValueChange` runs after the new value has been stored in the form. It
receives `{ newValue, event, reason, details }`:

```tsx
<RHFCountrySelect
  fieldName="country"
  control={control}
  valueKey="iso"
  onValueChange={({ newValue, event, reason, details }) => {
    setValue('state', '')
  }}
/>
```

Use `customOnChange` when you need to change what gets stored. It replaces the
default handling, so you must call `rhfOnChange` yourself with the value to
store. This example limits a multiple select to five countries: `onValueChange`
is **not called** when `customOnChange` is used.

```tsx
<RHFCountrySelect
  fieldName="countriesVisited"
  control={control}
  valueKey="iso"
  multiple
  customOnChange={({ rhfOnChange, newValue, event, reason, details }) => {
    if (newValue.length <= 5) {
      rhfOnChange(newValue);
    }
  }}
/>
```
