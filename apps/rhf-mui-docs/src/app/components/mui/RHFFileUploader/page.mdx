# RHFFileUploader

**RHFFileUploader** is a flexible file upload component for React Hook Form. It
supports:
- Single and multiple file uploads
- Drag-and-drop uploads
- Existing server-side files
- File type validation
- File size validation
- Upload count limits
- Custom upload button rendering
- Custom file item rendering
- Custom drop zone styling and behavior

## Usage

```tsx
import RHFFileUploader, { RHFFileUploaderProps, FileUploadError } from '@nish1896/rhf-mui-components/mui/file-uploader';
```

Here is a basic example of the component configured to accept a single file:

```tsx
import { useForm } from 'react-hook-form';

type FormValues = {
  resume: File | null;
};

const { control, handleSubmit } = useForm<FormValues>({
  defaultValues: { resume: null }
});

<form onSubmit={handleSubmit(values => console.log(values.resume))}>
  <RHFFileUploader
    fieldName="resume"
    control={control}
    registerOptions={{ required: 'Please attach your resume' }}
  />
</form>
```

Pass the `multiple` prop to allow selecting several files.

The stored value is a single `File`, or `null` when empty, and a `File[]` when
`multiple` is set. Use `null` (single) or `[]` (multiple) as the default value.
Removing the last file stores `null` for a single-file field and `[]` for a
multi-file field. `onValueChange` receives `{ newValue, event }`, where `event`
is the input change, drop or remove-button click that caused the change.

The component only manages the files. It doesn't list them, so render the
selected files with `renderFileItem` and the server-side ones with
`existingFiles` and `renderExistingFileItem` (see below).

A file object has the following properties:

```js
{
  lastModified: 1738870405923,
  lastModifiedDate: "Fri Feb 07 2025 01:03:25 GMT+0530 (India Standard Time)",
  name: "Picture.png",
  size: 860146,
  type: "image/png",
  webkitRelativePath: ""
}
```
When uploading files through an API, send them in a **FormData** object.

```ts
async function onFormSubmit(formValues: FormSchema) {
  const formData = new FormData();
  const { resume, pictures } = formValues;

  /* resume can be null, so handle the null check */
  resume && formData.append('resume', resume);

  Array.isArray(pictures) && pictures.forEach(file => {
    formData.append('pictures', file);
  });
  await sendFormData(url, formData);
}
```

[Multer](https://www.npmjs.com/package/multer) middleware. See:

### Multiple Files & Validation

`RHFFileUploader` can be configured to:
- Accept multiple files
- Restrict file types using `accept`
- Limit file size using `maxSize`
- Limit uploaded file count using `maxFiles`
- Handle upload validation errors
- Render custom upload buttons
- Render custom file items

```tsx
type FormValues = {
  pictures: File[];
};

const { control } = useForm<FormValues>({
  defaultValues: { pictures: [] }
});

<RHFFileUploader
  fieldName="pictures"
  control={control}
  multiple
  accept="image/*"
  maxFiles={3}
  maxSize={5 * 1024 * 1024}
  onUploadError={errors => {
    alert(`${errors.length} file(s) were rejected.`);
  }}
/>
```

Every incoming file, whether it is picked from the dialog or dropped, is checked
on its own:

- `accept` is a comma-separated list of MIME types (`image/png`), wildcards
  (`image/*`) and extensions (`.pdf`). Matching ignores case, and the same list
  also filters the browser's file dialog. An extension is compared with the part
  of the name after the last dot, so `.gz` matches `archive.tar.gz` but
  `.tar.gz` doesn't.
- `maxSize` is in bytes, so `5 * 1024 * 1024` is 5 MB.
- `maxFiles` caps the total. Files from `existingFiles`, files that are already
  selected and the incoming batch all count towards it, and only the excess
  files are rejected.

Rejected files are never added to the field value, while the valid files from
the same batch still are. With `multiple`, accepted files are appended to the
current ones. Without it, a valid file replaces the current one, and a rejected
file leaves the current one in place. In that mode the selected file isn't
counted by `maxFiles`, since it is replaced.

These checks run while files are being added. To block submission until a file
is present, or to enforce a minimum count, add a rule in `registerOptions`:

```tsx
<RHFFileUploader
  fieldName="pictures"
  control={control}
  multiple
  accept="image/*"
  registerOptions={{
    validate: files => files.length >= 2 || 'Upload at least two pictures'
  }}
/>
```

### Drag and Drop

Drag-and-drop uploads are enabled by default, but can be disabled using the
`disableDragAndDrop` prop.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  disableDragAndDrop
/>
```

### Custom Drop Zone

Customize the drop zone appearance and behavior using `dropZoneProps`.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  dropZoneProps={({ isDragging, disabled, error }) => ({
    sx: {
      borderColor: error
        ? 'error.main'
        : isDragging
          ? 'primary.main'
          : 'grey.400',
      opacity: disabled ? 0.5 : 1
    }
  })}
/>
```

Where:
```ts
type RHFFileUploaderDropZoneState = {
  /** Whether a file is currently being dragged over the drop zone. */
  isDragging: boolean;
  /** Whether the uploader is disabled. */
  disabled: boolean;
  /** Whether the uploader is currently displaying a validation error. */
  error: boolean;
};
```

### Custom Upload Button

Use `renderUploadButton` to provide a fully custom upload control.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  renderUploadButton={fileInput => (
    <Button
      component="label"
      variant="contained"
      startIcon={<UploadFileIcon />}
    >
      Upload Documents
      {fileInput}
    </Button>
  )}
/>
```

### Existing Files

Use `existingFiles` to display files that have already been uploaded and stored
on the server.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  existingFiles={[
    {
      name: 'contract.pdf',
      url: '/uploads/contract.pdf',
      size: 102400
    },
    {
      name: 'invoice.pdf',
      url: '/uploads/invoice.pdf'
    }
  ]}
/>
```

Existing files are rendered separately from newly uploaded files and are counted
toward the `maxFiles` limit.

### Custom File Rendering

Use `renderFileItem` to customize how newly uploaded files are displayed.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  multiple
  renderFileItem={({ file, index, removeFile }) => (
    <Stack
      direction="row"
      justifyContent="space-between"
      alignItems="center"
    >
      <Typography>
        {index + 1}. {file.name}
      </Typography>
      <IconButton onClick={removeFile}>
        <DeleteIcon />
      </IconButton>
    </Stack>
  )}
/>
```

The renderer receives:

```ts
{
  file: File;
  index: number;
  removeFile: (
    event: MouseEvent<HTMLButtonElement>
  ) => void;
}
```

### Custom Existing File Rendering

Use `renderExistingFileItem` to customize how server-side files are displayed.

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  existingFiles={[
    {
      name: 'contract.pdf',
      url: '/uploads/contract.pdf'
    }
  ]}
  renderExistingFileItem={({ file, index }) => (
    <Link
      href={file.url}
      target="_blank"
      rel="noopener noreferrer"
    >
      {index + 1}. {file.name}
    </Link>
  )}
/>
```

The renderer receives:

```ts
{
  file: {
    name: string;
    url: string;
    size?: number;
  };
  index: number;
}
```

### Handling value changes

Depending on your use case, you can use `customOnChange` to gain complete
control over file validation and form state updates, or use `onValueChange` to
respond to file uploads, removals, and clear actions after the field value has
changed.

#### customOnChange

Use `customOnChange` when you need full control over how uploaded files are
processed before updating the React Hook Form field value.

Unlike `onValueChange`, which is a notification callback, `customOnChange`
overrides the default update behavior.

<Callout type="warning">
When using `customOnChange`, you are responsible for calling `rhfOnChange`
manually. If `rhfOnChange` is not called, the form value will not be updated.
</Callout>

```ts
customOnChange?: ({
  rhfOnChange,
  newValue,
  event
}) => void;
```

**Example: Restrict Total File Size**

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  multiple
  customOnChange={({ rhfOnChange, newValue, event }) => {
    const files = Array.isArray(newValue)
      ? newValue
      : newValue
        ? [newValue]
        : [];
    const totalSize = files.reduce(
      (sum, file) => sum + file.size,
      0
    );
    const maxTotalSize = 20 * 1024 * 1024; // 20 MB
    if (totalSize > maxTotalSize) {
      alert('Total file size cannot exceed 20 MB');
      return;
    }
    rhfOnChange(newValue);
  }}
/>
```

**Example: Filter Files Before Saving**

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  multiple
  customOnChange={({ rhfOnChange, newValue, event }) => {
    const files = Array.isArray(newValue)
      ? newValue.filter(file => !file.name.startsWith('temp_'))
      : newValue;
    rhfOnChange(files);
  }}
/>
```

#### onValueChange

`onValueChange` is called whenever:
- Files are uploaded
- Files are removed
- The field is cleared

```tsx
<RHFFileUploader
  fieldName="documents"
  control={control}
  onValueChange={({ newValue, event }) => {
    console.log(newValue);
  }}
/>
```

### Upload Validation Errors

`onUploadError` is called with one `FileUploadErrorDetails` entry per rejected
file: `{ file, errors }`. `errors` lists the `FileUploadError` values that
apply, and a file can fail more than one check:

| Value | Reported when |
|---|---|
| `FileUploadError.sizeExceeded` (`'FILE_SIZE_EXCEEDED'`) | The file is larger than `maxSize` |
| `FileUploadError.invalidExtension` (`'FILE_TYPE_NOT_ALLOWED'`) | The file doesn't match `accept` |
| `FileUploadError.limitExceeded` (`'FILE_LIMIT_EXCEEDED'`) | The file exceeds `maxFiles` |

The callback isn't called when every file is accepted. Rejected files are not
part of the field value, so React Hook Form doesn't know about them. Use
`setError` to show the message on the field, and `clearErrors` once a batch is
fully accepted:

```tsx
import RHFFileUploader, {
  FileUploadError,
  type FileUploadErrorDetails
} from '@nish1896/rhf-mui-components/mui/file-uploader';

const { control, setError, clearErrors } = useForm<FormValues>({
  defaultValues: { pictures: [] }
});

const hadRejections = useRef(false);

function handleUploadError(rejected: FileUploadErrorDetails[]) {
  hadRejections.current = true;
  const messages = rejected.map(({ file, errors }) => {
    if (errors.includes(FileUploadError.sizeExceeded)) {
      return `${file.name} is larger than 5 MB`;
    }
    if (errors.includes(FileUploadError.invalidExtension)) {
      return `${file.name} is not an image`;
    }
    return `${file.name} was not added: too many files`;
  });
  setError('pictures', { type: 'upload', message: messages.join(', ') });
}

<RHFFileUploader
  fieldName="pictures"
  control={control}
  multiple
  accept="image/*"
  maxFiles={3}
  maxSize={5 * 1024 * 1024}
  onUploadError={handleUploadError}
  onValueChange={() => {
    if (!hadRejections.current) {
      clearErrors('pictures');
    }
    hadRejections.current = false;
  }}
/>
```

`onUploadError` runs just before `onValueChange` in the same event, and
`onValueChange` is still called when every file was rejected, with the unchanged
value. Clearing the error there unconditionally would remove it right after it
is set, so remember whether the batch had rejections, as above.

### Accessibility
When using a custom upload button:

- Ensure the button uses `component="label"`.
- Render the provided `fileInput` somewhere inside the label.
- Add `tabIndex={-1}` to custom buttons when appropriate to avoid duplicate
  focus targets.

File dialogs can only be opened through direct interaction with a file input or
its associated label element.
