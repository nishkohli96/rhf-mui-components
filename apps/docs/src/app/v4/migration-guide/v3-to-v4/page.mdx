# Migrating from v3 to v4

- **MUI v5 is no longer supported.** Please upgrade **Material UI** to `v6` or `v7`, or
continue using the latest published `v3` version of this package.
- The `errorMessage` prop has been deprecated across all components and **will be removed**
in the next major upgrade. Field errors are now handled internally.

## Global breaking changes

### `onValueChange` signature updated

The function now accepts a single object instead of positional arguments, of the form:

```ts
({ newValue, event, ...otherArgs })
```

where:
- `newValue` — the latest value of the field after user interaction.
- `event` — the event that triggered the value update.
- `otherArgs` — additional arguments specific to each component's implementation.

This change keeps the signature consistent with the `customOnChange` prop across all
components, whose signature is of the form:

```ts
({ rhfOnChange, newValue, event, ...otherArgs })
```

### React Hook Form disabled state is now respected

Components now read the `disabled` value provided by React Hook Form's `Controller` field
state. This means a form-level disabled state passed through `useForm({ disabled: true })`
disables supported components automatically.

<Callout type="warning">
  Disabled fields follow React Hook Form and native form behavior. Depending on how you submit
  or serialize values, disabled fields may be omitted from the submitted payload.
</Callout>

### Date & Time Picker imports updated

With additional variants from MUI Pickers (`Desktop`, `Mobile` and `Static`), imports have
been simplified and made more explicit.

```diff
- import RHFDatePicker from '@nish1896/rhf-mui-components/mui-pickers/date';
+ import {
+   RHFDatePicker,
+   RHFMobileDatePicker
+ } from '@nish1896/rhf-mui-components/mui-pickers/date';
```

## Component-specific changes

The following components include new features, behavioral changes, and breaking API updates
that may require code changes when migrating from `v3` to `v4`.

### Autocompletes

- `RHFAutocomplete` and `RHFMultiAutocomplete` now support the `freeSolo` prop, allowing users
to enter values that are not present in the provided `options`.
- If enabling `freeSolo`, review any custom `renderValue`, `renderTags`, or `renderOptionLabel`
implementations to ensure they correctly handle both option objects and user-entered string
values (for example, using `typeof value === 'string'`).

### [RHFFileUploader](/v4/components/mui/RHFFileUploader)

**Added**
- Drag-and-drop uploads (enabled by default, can be disabled using the `disableDragAndDrop` prop).
- Support for pre-existing server-side files via `existingFiles`.
- Support for removing uploaded files via the `removeFile` helper provided to `renderFileItem`.

**Removed props**

The following props have been removed:
- `errorMessage` — validation errors are now derived automatically from React Hook Form state.
- `hideFileList` — file rendering is now fully controlled via `renderFileItem` and `renderExistingFileItem`.
- `showFileSize` — file size rendering must now be handled within custom file renderers.

**Breaking changes**
- `onValueChange` now receives a single object argument instead of positional parameters.
- `renderFileItem` now receives an object containing `file`, `index`, and `removeFile`.
- `onUploadError` now returns file-specific validation details as an array of `{ file, errors }`
objects instead of separate error and rejected-file arrays.
- When `multiple` is enabled, newly uploaded files are appended to the current RHF field value
instead of replacing it.
- `maxFiles` validation now also counts `existingFiles`.
- Built-in required validation treats `existingFiles.length > 0` as satisfying the required rule.
- The signature and return type of `validateFileList` has also been updated.

```diff
  const {
    acceptedFiles,
-   rejectedFiles,
-   errors
- } = validateFileList(fileList, '*', 5 * 1024 * 1024, 3)
+   rejectedFiles
+ } = validateFileList(fileList, {
+   accept: '*',
+   maxSize: 5 * 1024 * 1024,
+   maxFiles: 3
+ });
```

where `rejectedFiles` is an array of type:

```ts
type FileUploadErrorDetails = {
  /** File that failed upload validation. */
  file: File;
  /** Validation errors reported for the file. */
  errors: FileUploadError[];
};
```

**Callback migration**

```diff
  <RHFFileUploader
    fieldName="documents"
    control={control}
    multiple
-   onValueChange={(acceptedFiles, event) => {
-     console.log(acceptedFiles, event);
-   }}
+   onValueChange={({ newValue, event }) => {
+     console.log(newValue, event);
+   }}

-   onUploadError={(errors, rejectedFiles) => {
-     console.log(errors, rejectedFiles);
-   }}
+   onUploadError={fileErrors => {
+     fileErrors.forEach(({ file, errors }) => {
+       console.log(file.name, errors);
+     });
+   }}

-   renderFileItem={(file, index) => (
-     <UploadedFile key={file.name} file={file} index={index} />
-   )}
+   renderFileItem={({ file, index, removeFile }) => (
+     <UploadedFile
+       file={file}
+       index={index}
+       onRemove={removeFile}
+     />
+   )}

-   hideFileList
-   showFileSize
-   errorMessage={errors?.documents?.message}
  />
```

**Refer to the updated [RHFFileUploader](/v4/components/mui/RHFFileUploader)
documentation for complete usage examples and migration details.**

### [RHFCountrySelect](/v4/components/mui/RHFCountrySelect)

**Changed**
- When `valueKey` is provided, selected value(s) are stored using the specified country property.
- When `valueKey` is omitted, selected value(s) are stored as complete country objects.

<Callout type="warning">
  If you previously relied on the default `valueKey` behavior (i.e. `iso`),
  review your form values and submission payloads after upgrading.
</Callout>

### [RHFColorPicker](/v4/components/misc/RHFColorPicker)

**Removed**
- `value` prop is no longer needed — the selected color value is now derived automatically
from React Hook Form state.

### [RHFPhoneInput](/v4/components/misc/RHFPhoneInput)

**Added**
- The country dropdown now includes an inline search field by default.

**Changed**
- The field value is now stored as an `RHFPhoneInputValue` object instead of a plain `string`,
providing access to the selected country, dial code, and national phone number.

```diff
  import type { RHFPhoneInputValue } from '@nish1896/rhf-mui-components/misc/phone-input';

  type FormValues = {
-   phoneNumber: string;
+   phoneNumber: RHFPhoneInputValue;
  };
```

```diff
  const { control } = useForm<FormValues>({
    defaultValues: {
-     phoneNumber: '+918885511000'
+     phoneNumber: {
+       phone: '+918885511000',
+       country: 'in',
+       dialCode: '91',
+       phoneNo: '8885511000'
+     }
    }
  });
```

**Validation changes**

Update string-based validations to read from the structured value.

```diff
  <RHFPhoneInput
    fieldName="phoneNumber"
    control={control}
    registerOptions={{
      required: 'Phone number is required',
-     validate: value =>
-       value.length >= 6 || 'Enter a valid phone number'
+     validate: value =>
+       value.phoneNo.length >= 6 || 'Enter a valid phone number'
    }}
  />
```

<Callout type="warning">
  If your API still expects a string, submit `phoneNumber.phone`. Use `country`, `dialCode`, and
  `phoneNo` when your backend needs the selected country or the national number separately.
</Callout>

`onValueChange` now receives `{ newValue, phoneData }`.

```diff
  <RHFPhoneInput
    fieldName="phoneNumber"
    control={control}
-   onValueChange={phoneData => {
-     console.log(phoneData.phone);
-   }}
+   onValueChange={({ newValue, phoneData }) => {
+     console.log(newValue.phone, phoneData.country);
+   }}
  />
```

**Removed**
- `value` prop is no longer needed — it is now derived automatically from React Hook Form state.
- `errorMessage` prop — field errors are now derived automatically from React Hook Form state.
- `phoneInputProps.hideDropdown` has been removed. Use `phoneInputProps.forceDialCode` when you
want to lock the selected country/dial code.

```diff
  <RHFPhoneInput
    fieldName="phoneNumber"
    control={control}
    phoneInputProps={{
      defaultCountry: 'in',
-     hideDropdown: true
+     forceDialCode: true
    }}
-   value={watch('phoneNumber')}
-   errorMessage={errors?.phoneNumber?.message}
  />
```

**Refer to the updated [RHFPhoneInput](/v4/components/misc/RHFPhoneInput)
documentation for complete usage and examples.**
